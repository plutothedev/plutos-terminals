# v0.1.13 — header button style picker (6 designs)

Pluto's framing: "ok well the buttons are the same in the header still can we design few different header button designs"

The skin picker (v0.1.10–v0.1.12) changes colors but every skin still rendered the same bordered-rectangle button shape. v0.1.13 adds a second axis: **HEADER BUTTONS** dropdown in ⚙️ settings with 6 design directions. Combines with any skin.

## What's new

### 🔘 6 button designs, user-pickable

Open ⚙️ → **HEADER BUTTONS (LIVE PREVIEW)**:

1. **Default** — bordered rectangle (current). Subtle, familiar.
2. **Pill** — fully rounded ends, soft filled background, lift on hover. Friendlier feel.
3. **Ghost** — no border at rest, underline appears on hover. Most minimal.
4. **Filled** — every button is a solid accent CTA. Loud, confident. (⚙️ settings stays muted to avoid screen-shouting.)
5. **Bracket** — `[ label ]` terminal aesthetic, no borders. Pure terminal feel.
6. **Chip** — rounded corners with subtle shadow + hover lift. Modern SaaS.

Selection persists in localStorage as `st.headerButtonStyle`. Default for existing users: Default.

### Architecture

Buttons are an **orthogonal axis** to skins. Skin sets colors via CSS vars; button-style sets shape / border / padding / hover behavior via `[data-phn-btn-style="<id>"]` on `<html>`. Combine any of the 10 skins with any of the 6 button styles = 60 distinct looks.

- New `HEADER_BUTTON_STYLES` array in `headerSkins.js` (id, label, description per style)
- New `applyGlobalButtonStyle(id)` helper sets `data-phn-btn-style` on `<html>` (mirrors `applyGlobalSkin`)
- Per-style CSS rules placed AFTER skin rules in the injected stylesheet so they win equal-specificity ties
- TerminalsTab `useEffect` calls `applyGlobalButtonStyle(headerButtonStyleId)` on change
- SettingsModal new `HEADER BUTTONS (LIVE PREVIEW)` field — live-applied via save() on selection

### Implementation notes

- Button styles use `!important` only on properties where the skin's `:hover` rule would otherwise clobber an intentional behavior (e.g. ghost mode keeping background transparent on hover instead of taking the skin's hover-bg)
- `color-mix(in srgb, currentColor 6%, transparent)` used for pill/chip soft fill — Tauri's webview supports this
- Filled mode skips the muted ⚙️ button (`.phn-muted` selector exclusion) so settings doesn't shout for attention with the rest

## Known limitations (deferred)

- **TerminalPanel tab strips** still hardcoded — tabs at the top of each panel don't follow skin yet (visible but not broken)
- **Filled mode + Daylight skin** — accent text on white-page background works but lacks visual weight; might need a darker variant in a follow-up
