## Pluto's Terminal v0.7.5

RDP sign-in works, settings sync works over https, and the phone tells you why notifications are off. Full detail in `CHANGELOG.md`.

### Fixed
- **RDP sign-in with Network Level Authentication works.** Until now the app
  sent the server the wrong form of its own public key during sign-in, so a
  server that requires NLA (the Windows default) always refused it. Saved
  certificate pins stay valid.
- **Settings sync works with an `https://` repository address.** Every https
  address used to fail with "unsupported URL protocol", although Settings
  suggests one.
- **A dialog you answer from the phone is no longer answered again by
  auto-approve** on the desktop, and typing on the phone counts as activity in
  that pane.
- **RDP screens use RemoteFX again**, and a damaged screen update is followed
  by a redraw request instead of leaving the picture stale.

### New
- **The phone says why notifications are off.** On the phone page a bell
  button appears when push could not be set up, with the reason; tap it to try
  again (on iPhone, the tap is what lets the browser ask for permission).

### Safer
- **Settings sync without a token sends your Windows sign-in only to servers
  on your own network.** A public server that asks for a sign-in is told to
  use an access token instead.
- **Typing from the phone never lifts the auto-approve hold** on a resumed
  Claude pane; only typing at the desktop does.
- **Phone notifications are now encrypted and signed by the app itself**
  (the same format phones already accept; nothing to set up again), with no
  redirects followed.
- DOMPurify 3.4.17, rustls-webpki 0.103.16, webpki-roots 1.0.11 and libz-sys
  1.1.31 clear recent advisories, and the RDP and notification libraries move
  off the vulnerable crypto-bigint (RUSTSEC-2026-0387).
