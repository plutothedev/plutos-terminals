# v0.1.32 — scrollback caps raised 50×

Polish pass on the v0.1.29 → v0.1.31 persistence work. Scrollback was restoring, but only the last ~100 KB per pane — enough for short sessions, not enough for a claude code conversation or a long debug session.

## What changed

Two limits, both bumped:

**Disk persistence:**
- `SCROLLBACK_FILE_MAX_BYTES`: 200 KB → **10 MB**
- `SCROLLBACK_FILE_KEEP_BYTES`: 100 KB → **5 MB**

That's roughly 50,000 lines of typical terminal output per pane, persisted to disk. With ~8 packed panes, total disk usage caps around 80 MB — rounding error on modern storage.

**In-memory xterm scrollback:**
- `scrollback`: 5000 lines → **10000 lines**

Bumped because xterm's in-memory cap had become the binding constraint on what's visible after restore. With disk now holding up to ~50K lines per pane, xterm at 5K would silently drop most of it on replay. 10K lines is still memory-modest (~16 MB per pane at full fill, ~150 MB across 8 panes packed).

## What you'll see

The pane that previously couldn't scroll all the way to your earliest pre-quit output now can. Disk has more, xterm has more.

Pre-v0.1.32 scrollback files that were already truncated stay truncated — the bigger budget applies forward only, not retroactively. If you want full fidelity on existing panes, run something new in them now so the larger cap kicks in for the new content.
