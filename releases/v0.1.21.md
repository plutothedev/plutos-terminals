# v0.1.21 — multi-window blocker fix (shared user-level state)

Critical pre-launch fix. Found by audit pass before recording the YouTube video.

## What was broken

Opening a second window via `Ctrl+K → 🪟 Open new window` triggered:

1. **Welcome screen re-prompt** — user had to re-paste the API key
2. **Onboarding tour replay** — 4-step walk-through fired again

Root cause: `welcomeDone`, `anthropicKey`, and `terminalsOnboarded` were stored in per-window localStorage (keyed by `?w=<id>`). Each new window saw fresh empty state for these flags and treated the user as a first-time visitor.

## Fix

Split state into two scopes:

- **Per-window state** (`plutos-terminals:state:v0[:<id>]`) — panels, tabs, skin, density, recent packs, projects. Each window keeps these independent.
- **Shared user state** (`plutos-terminals:user:v0`) — `welcomeDone`, `anthropicKey`, `terminalsOnboarded`. All windows share these via the same localStorage key.

Now opening a 5th window goes straight to the terminal grid: no welcome, no tour, key already injected into spawned shells.

### Migration

On first launch of v0.1.21, existing users with these flags in their old per-window state get them copied to the new shared store automatically. One-shot synchronous migration in App.jsx's `useState` initializer — no flicker, no Welcome screen briefly appearing for migrated users.

### Cross-window sync

App.jsx listens for `storage` events on `plutos-terminals:user:v0`. If window 1 dismisses the tour while window 2 is already open, window 2 picks up the change immediately without a refresh.

### Factory reset

Updated to wipe all per-window states (any key starting with `plutos-terminals:state:v0`) AND the shared user state. One-click clean slate.

## Component prop changes

- `TerminalsTab` — accepts `userSt` + `saveUser` props alongside existing `st` + `save`
- `SettingsModal` — same pair, plus reads/writes anthropicKey via `userSt`/`saveUser`
- `SetupChecker` — accepts `userSt`, falls back to `st.anthropicKey` for legacy users
- `TerminalPane` — extra-env injection reads userState first, falls back to window state for not-yet-migrated users
