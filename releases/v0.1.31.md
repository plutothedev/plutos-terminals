# v0.1.31 — scrollback survives the shell's startup

The v0.1.30 fix made `scrollback_load` return real content, and the `─── scrollback restored ───` marker started firing — but pluto reported the replayed scrollback flashed briefly then disappeared.

## What was wrong

The Windows PowerShell 5 fallback shell (used when `pwsh.exe` PowerShell 7 isn't installed) was being spawned with this command line:

```
powershell.exe -NoLogo -NoExit -Command "Import-Module PSReadLine -ErrorAction SilentlyContinue; Clear-Host"
```

The `Clear-Host` was originally added to suppress PS 5's startup banner. But `-NoLogo` already does that. So `Clear-Host` was redundant — and when `[Console]::Clear()` ran through ConPTY, it issued sequences that wiped the scrollback buffer xterm.js had just been populated with by `scrollback_load`.

Order of operations:
1. Pane mounts → xterm created
2. `replayScrollback()` runs → previous session's content + `─── scrollback restored ───` marker visible in xterm
3. PTY spawns → shell starts, runs `Clear-Host` → xterm scrollback wiped
4. Live prompt appears in an empty terminal

Visible just long enough for pluto to see it before the shell killed it.

## What changed

One-line fix. Removed `Clear-Host` from the PS 5 fallback args. `-NoLogo` still suppresses the banner; nothing else needs to clear the screen.

The pwsh 7 path (`pwsh.exe -NoLogo`) was never affected — no Clear-Host there.

## What you'll see

Scrollback now persists into the live session. On relaunch you see your previous output, the `─── scrollback restored ───` marker, then the live prompt below. The replayed content stays in xterm's scrollback so you can scroll up to see it for the rest of the session.
