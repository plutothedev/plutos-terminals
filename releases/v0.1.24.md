# v0.1.24 — example pack systemPrompt cleared

One-line fix flagged in the v0.1.23 pre-launch test report.

## What was broken

`prompt-packs/example.deck.json` had its `systemPrompt` field set to a meta-explanation:

> *"Optional. If present, this string is auto-typed into the PTY 2 seconds after spawn — perfect for role priming, persona, or task framing. Empty / missing means no auto-prompt."*

Loading the example pack would auto-type that text into a shell where there was no Claude session running (the example pack's startCommand is just an echo banner, no `claude`). The shell would try to execute "Optional. If present…" as a command and emit a confusing error.

The README and pack description both warn users not to load the example pack ("schema reference only — go to one of the practical packs"), so casual users wouldn't hit this. But it was a real glitch and a 5-second fix.

## What changed

`prompt-packs/example.deck.json` line 16: `systemPrompt` value cleared from the long meta-comment to `""` (empty string).

The `applyPack` flow (TerminalsTab.jsx) and the systemPrompt-write block (TerminalPane.jsx) both already short-circuit on empty strings — `sysPrompt.trim().length > 0` is the gate. So an empty value is the canonical "no auto-prompt" signal.

The schema-reference utility of the example pack is preserved via the existing `notes[]` field which already documents what `systemPrompt` does:

> *"systemPrompt: optional per-tab string written to the PTY 2s after startCommands run. Used to prime Claude / the agent in that tab."*
