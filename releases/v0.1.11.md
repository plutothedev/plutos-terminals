# v0.1.11 — skin themes the WHOLE APP (page + sidebar + status bar + terminal bg)

Pluto's framing: "i want the theme to replace the whole app not just the header and also the black background of the terminal be the color of the theme and there be an option to have the regular black background in the terminal."

v0.1.10 shipped 10 header skins. v0.1.11 extends each skin so the picked theme paints the entire app — page background, sidebar, status bar, and the terminal's xterm background. Plus a settings toggle to override the terminal back to pure black.

## What changed

### Skin = whole app
Previously the skin only restyled the top toolbar. Now the skin sets CSS variables on the app root that every surface reads:

- **Page background** — outermost area between header and status bar
- **Sidebar** — projects panel on the left
- **Sidebar header** — "PROJECTS" strip
- **Status bar** — bottom version/cost/links strip
- **xterm terminal background** + **foreground** + **cursor** + ANSI palette — the actual terminal output area inside each pane

So picking **Solarized Amber** turns the whole app warm-amber (not just the header chrome). Picking **Daylight** flips the app to a real light theme — page, sidebar, terminal, all white. Picking **Synthwave Sunset** runs purple→orange gradient through the header and gives every terminal a deep-purple background.

### "Pure black terminal background" override
New checkbox in ⚙️ settings: **TERMINAL BACKGROUND → Use pure black terminal background**.

Off (default): xterm bg follows the skin (e.g. amber background for Amber skin).
On: xterm bg forced to `#000000` regardless of skin. Header/sidebar/status still themed.

For when you love a skin's chrome but want the terminal output area to feel like a classic black terminal.

### Implementation

- `headerSkins.js` extended: each skin now exports an `xterm` object (full xterm.js theme with bg / fg / cursor / 16-color ANSI palette).
- New CSS variables per skin: `--phn-page-bg / --phn-surface-bg / --phn-surface-alt-bg / --phn-surface-border / --phn-text-fg / --phn-text-active / --phn-text-dim / --phn-link`.
- New universal classes that read those vars: `.phn-page / .phn-statusbar / .phn-sidebar / .phn-sidebar-header / .phn-statusbar-link / .phn-statusbar-divider`.
- TerminalsTab outermost div now carries `data-phn-skin={skinId}` + `className="phn-page"` (was inline `style={{ background: PAGE_BG }}`).
- Status bar uses `className="phn-statusbar"`. Sidebar uses `className="phn-sidebar"`.
- TerminalPane refactored: accepts `xtermTheme` prop directly (was `themeKey` + `getTheme(themeKey)` lookup). Live theme updates work via `useEffect` on the prop.
- `getSkinXtermTheme(skinId, { pureBlackTerminal })` helper handles the override.

### Removed

- **Toolbar terminal-theme picker** — the header dropdown for "Pluto Dark / Dracula / Solarized Dark / Monokai / Gruvbox / Pluto Light". Skin handles xterm theming now; pure-black toggle is the override. One less axis to think about.
- `themes.js` is no longer imported by TerminalsTab or TerminalPane (the file remains in the repo for now; will be removed in a future cleanup if confirmed unused elsewhere).

### Status bar tweak
Status bar now shows **terminal bg: skin** or **terminal bg: pure black** in place of the old `theme: <name>` text — reflects the new mental model.

## Known limitations (not fixed v0.1.11)

- **Modal styling is still hardcoded** — settings/toast/confirm modals use a fixed dark palette. With Daylight skin, modals look out of place (dark on white). Skinning modals is the next pass.
- **Glass skin's `--phn-surface-bg` uses `rgba(...)` directly in CSS — works for header/sidebar but isn't actually translucent against the page (we'd need explicit transparency support in flex layout). The visual works as a "dark glass" without the full backdrop-blur effect outside the header.
- **Status bar skin treatment is minimal** — uses surface-bg + dim text. Acceptable for all skins but the deep gradients (sunset, neon) lose some drama at the bottom.
