# v0.1.7 — drop agent grid + packs auto-launch claude

The "agent grid" toggle (v0.1.2 → v0.1.6) was UX theater — 4 Claude tabs with role-labels but no actual specialization. After 5 releases iterating on its toggle UI, the honest answer is to drop it and refocus on the real differentiator: **prompt packs**.

## What changed

- **Removed the `💻 TERMINAL ↔ 🤖 AGENT GRID` toggle entirely.** Including the `ViewToggle` component, `AGENT_GRID_PRESET` constant, `switchToAgentGrid` / `switchToTerminal` / `onToggleViewMode` callbacks, `st.viewMode` / `st.previousPanels` state, and the `⚡ agent grid` quick-spawn button (already removed in v0.1.6 but worth noting). Header now starts with the `TERMINALS` label, just like the original Lyfe component.
- **Bundled packs now actually launch `claude`.** Previously every pack's `startCommands` was an `echo` reminder to type `claude` manually. v0.1.7 packs run `claude` directly as the first command. If the user has the CLI + API key set up, the session boots straight into Claude Code. If not, the user gets a clear "command not found" error instead of an echoed reminder they didn't read.

Updated packs:
- `claude-code-basic.deck.json` — 1 pane, runs `claude`
- `dual-claude-pair.deck.json` — 2 panes, both run `claude` (code + plan splits)
- `trading-workflow.deck.json` — Claude analysis pane runs `claude`; scratch + journal stay shells
- `pluto-personal-strategist.deck.json` — strategist pane runs `claude` (already did, just removed the echo prefix)

## Path forward — refocus on packs

Next features (Tier 1 in the brainstorm):
1. **Per-tab system prompt injection** — packs gain a `system_prompt` field; after `claude` boots, the prompt is sent as the first message. Real role specialization.
2. **MCP real auto-install** — `🔌 MCPs` modal goes from "copy command" to "click install."
3. **Pack import from URL** — paste a gist/raw URL to load any community pack.

These three close the "packs are real specialization, packs share via link, MCPs install with one click" loop.
