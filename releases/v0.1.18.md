# v0.1.18 — bundle 5: asciinema session recording

🎬 **Record any terminal tab and export as an asciinema-format `.cast` file** that can be replayed in browsers, embedded in docs, or shared on social.

## What's new

### Recording

Press `Ctrl+K` → **🎬 Start recording active tab** to begin recording. While recording, every byte of PTY output is captured with millisecond timestamps to an in-memory buffer. The status bar shows a magenta **● rec** indicator (with a multiplier if multiple tabs are recording at once); click it to jump to the recording tab and save.

When you're done: `Ctrl+K` → **⏹ Stop & save recording** opens a native file save dialog defaulting to `plutos-terminals_<tab-label>_<iso-date>.cast`. The file is asciinema v2 format — playable on [asciinema.org](https://asciinema.org), embeddable via `<asciinema-player>`, or just readable as JSONL.

### Architecture

- **`src/features/terminals/recording.js`** — module-level Map keyed by `tabId`. API: `startRecording / stopRecording / pushOutput / isRecording / activeTabIds / onChange`. In-memory only until `stopRecording` returns the formatted `.cast` content.
- **TerminalPane PTY listener** calls `pushOutput(tabId, payload)` on every incoming chunk. No-op when there's no active recording for that tab — zero overhead when not recording.
- **`save_text_to_file`** Tauri command — opens native rfd save dialog with extension filter, writes contents to chosen path. Returns the saved path (or null if user canceled). Used by the cast export and reusable for future "export X to file" features.
- **TerminalsTab** subscribes to `recording.onChange()` to update the status bar indicator + command palette labels reactively.

### Asciinema v2 format

```
{"version":2,"width":80,"height":24,"timestamp":1717718400,"title":"Claude — coder","env":{"TERM":"xterm-256color"}}
[0.000123,"o","[?25h"]
[0.045621,"o","claude\r\n"]
[0.612344,"o","Welcome to Claude Code.\r\n"]
...
```

JSONL — header object on line 1, then one event array per subsequent line. Replayable on any asciinema player.

## Limitations / notes

- Recording is per-tab. If you want a multi-pane workflow recording, record each pane separately.
- The recording starts when you press start, not retroactively — scrollback before the start point isn't included.
- Width / height are hardcoded to 80×24 in the header. xterm internally fits to its container, but the cast file's declared dimensions don't dynamically follow resizes (cast format is fixed-size). Most asciinema viewers handle mismatches fine; just be aware.
- App restart kills any in-progress recordings (they're in-memory only). Save before quitting.
