# v0.1.9 — plug-n-play scrub

Anything that assumed the downloader has Pluto's specific second-brain vault setup got removed so a fresh download Just Works without compatibility surprises.

## What's removed

- **`pluto-personal-strategist.deck.json`** — bundled pack that referenced Pluto's machine paths + assumed an Obsidian-style vault at `${VAULT}`. Most downloaders don't have one. Pluto can keep his version locally via export/import.
- **`${VAULT}` field** in the ⚙️ settings modal — was specifically for routing the deleted pack. The underlying env-var expansion infrastructure (any `${VARNAME}` in pack `cwd` resolves against process env) stays — pack authors can still use whatever env vars users have set in their shell before launching the app.
- All documentation references to the removed pack + vault concept (`prompt-packs/README.md`, `HOW_TO_USE.md`, root `README.md`).

## What stayed

- `claude-code-basic` — single Claude Code pane (generic)
- `dual-claude-pair` — code + plan panes (generic)
- `trading-workflow` — Claude analysis + Python scratch + dated journal (clearly labeled "Pluto Style" so users self-select; ICT-trader-specialized but doesn't break for anyone)
- `example` — schema reference

`${USERPROFILE}` and `${HOME}` continue to work for cross-machine pack paths since they're auto-set by the OS.

## Plug-n-play status

A fresh download → install → setup checker passes → load `claude-code-basic` → `claude` boots → systemPrompt arrives → working session. No vault, no `${VAULT}` field, no machine-specific paths. Same path on any Windows machine with Node + Claude CLI + an Anthropic key.

## What's in this release

- **`plutos-terminals_0.1.9_x64.msi`** — Windows installer
- **`plutos-terminals.exe`** — standalone binary
