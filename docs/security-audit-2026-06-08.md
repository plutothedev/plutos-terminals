# Pluto's Terminals — Full Codebase Security & Correctness Audit

**Date:** 2026-06-08  
**Scope:** entire `001-remote-sessions-parity` branch at HEAD `508f0a3` (v0.3.5; verified == GitHub origin). ~22k LOC: 14 Rust files (`src-tauri/src`) + ~90 JS/JSX files (`src`) + companion web bundle + Tauri config.  
**Method:** 68-agent static audit. 30 finder agents (26 subsystem units covering every file once + 4 adversarial security lenses), each applying 8 lenses (correctness, security, resource/concurrency, cleanup, altitude); one adversarial verifier per unit (REFUTED dropped); 4 fresh gap-sweep agents over the highest-risk clusters, also verified. No code was run — pure static review.  
**Result:** 185 findings — **2 critical, 22 high, 58 medium, 103 low**. By category: 64 security, 30 resource, 51 correctness, 5 altitude, 17 concurrency, 18 quality.

> **Verdict.** The app is feature-complete and the core terminal/PTY/SSH machinery is sound. The weak spot is **security posture**, not functionality — and it clusters in four places: (1) two RCE-class command-injection paths, (2) secrets stored in plaintext `localStorage` while the code/docs claim they live only in the OS keychain, (3) a disabled Content-Security-Policy that amplifies every other web-surface bug, and (4) the phone companion server. None of these block daily use as a personal tool, but they should be closed before this is shipped to "the Pluto community" as a download. Correctness debt is concentrated in resource leaks (handles/threads/listeners never cleaned up) and React stale-state/effect races.

## Cross-cutting themes (fix the root, not the leaf)

1. **`cmd /C start "" <path>` is the universal "open" primitive and an injection sink.** `open_path` (commands.rs:110) does not caret-escape cmd metacharacters; it is fed attacker-influenced strings by clickable terminal links (Critical #1) and the update banner. The code's own comment at commands.rs:421 documents the hazard but only for the hard-coded-catalog case. Fix `open_path` once (reject metacharacters / use ShellExecute) and every caller is covered.
2. **Secrets are split inconsistently between the keychain and plaintext localStorage.** SSH creds correctly use `vault.rs` → OS keychain; but provider/LLM API keys, the legacy Anthropic key, and the master-password hash sit in cleartext localStorage — directly contradicting the documented invariant and `vault.rs`'s own comment. Route all secrets through the vault.
3. **CSP is `null`.** This is the single highest-leverage hardening: it both enables the XSS execution path (terminal/markdown/LLM output is rendered in-app) and the `connect-src` exfiltration channel for the plaintext keys above. Set a restrictive CSP.
4. **The master-password "lock" is cosmetic.** Unsalted single-shot SHA-256, 4-char minimum, bypassable via a sessionStorage flag or by deleting the hash from localStorage — and it "protects" keys that are already plaintext-readable. Either make it a real KDF-derived gate enforced in Rust, or document it as decorative.
5. **Companion server trusts the network perimeter too much.** Only `/ws` checks the token; every HTTP route (including a `ServeDir` of the full desktop `dist` bundle) is unauthenticated, `list_directory` is an un-jailed full-filesystem read, the token compare is not constant-time, and `tailscale serve` is left proxying after stop. Add auth middleware on the whole router and jail filesystem RPCs.
6. **Multi-window gating is applied inconsistently** (companion listeners are gated to the primary window; the three companion *push* effects are not → secondary windows clobber the phone's mirror), and **`runAndCapture` has no command↔block correlation** (root cause of several Agent-Mode wrong-output bugs).

### 1. Clickable-path link regex permits shell metacharacters (& | ^ %), and the path flows into open_path which runs `cmd /C start "" <p>` on Windows — argument/command injection from attacker-influenced terminal output.

- **Location:** `src/features/terminals/TerminalPane.jsx:534`  
- **Category / severity / verdict:** security · critical · CONFIRMED  
- **Failure scenario:** The link provider's regex is `/(?:~|\/)[^\s'"()<>:]{2,}(?::\d+(?::\d+)?)?/g`. The negated class only excludes whitespace, quotes, parens, angle brackets and colon — it ALLOWS &, |, ^, %, etc. Terminal output is attacker-influenceable (a malicious remote SSH server's MOTD, `cat` of a crafted file, `git log`, `curl` output). An attacker prints a token like `/tmp/x&calc.exe` (or `/a|powershell ...`), which gets underlined as a clickable link. When the user clicks it, activate() calls invoke('open_path', { path: raw.replace(/:\d+.../, '') }). open_path (src-tauri/src/commands.rs:121) runs `Command::new("cmd").args(["/C","start","",&p])`; cmd.exe interprets the `&`/`|`/`^` in p as command separators, executing the attacker's payload. No allow-list, no existence check, no metachar rejection anywhere in the chain.  
- **Suggested fix:** Tighten the link regex to reject shell metacharacters (drop &, |, ^, %, ;, $, ` from the allowed set), and before invoking open_path verify the resolved path actually exists as a file/dir on disk and is not a scheme/UNC. Better: have open_path reject any path containing cmd metacharacters and use ShellExecute / a non-cmd spawn on Windows instead of `cmd /C start`.
